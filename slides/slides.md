# Введение
Задача векторного поиска

В множестве векторов $X \subset \R^d$ найти $k$ ближайших соседей вектора-запроса $q$: $\underset{u \in X}{\operatorname{arg\,min}} \ \delta(q, u).$

Здесь и далее мы будем использовать расстояние $L_2$: $\delta(x, y) = \|x - y\|_2$ и говорить про задачу приближённого поиска ближайших соседей (ANN).

Где встречается задача векторного поиска:

- Semantic search
- RAG
- RecSys
- Multimodal search

# Постановка задачи

Задача: понять, насколько синтетические данные воспроизводят результаты оценки ANN-алгоритмов на реальных эмбеддингах.

- не завышаются ли метрики на синтетике?
- повторяет ли синтетика распределение и геометрию настоящих данных?
- при каких генераторах и режимах метрики близки к результатам на настоящих данных?

# Обзор решений

Рассматриваем алгоритмы, которые обучаются *воспроизводить данный датасет.*

<div class="grid grid-cols-4 gap-4 mt-4">
<div>

**Перевыборка и возмущение**

К исходным точкам добавляют шум, чтобы получить локальные вариации данных

Примеры: jitter, perturbation

</div>
<div>

**Параметрические модели**

Распределение данных аппроксимируют смесью вероятностных компонент

Пример: диагональная GMM

</div>
<div>

**Нейросетевые модели**

Модель обучается генерировать данные из сложного распределения, часто через латентное представление

Примеры: VAE, GAN, diffusion, Normalizing Flows

</div>
<div>

**Кластерно-геометрические модели**

Явно задают кластеры, локальное подпространство и шум вне него

Пример: cuVS

</div>
</div>

# Метрики

Роутер выбирает $k$ шардов (здесь $k = 3$ из 5). Метрика $\rho_k(q)$ — какая доля из 100 истинных ближайших соседей запроса $q$ попала в выбранные шарды: $\rho_k(q) = 92/100 = 0.92$.

# Метрики

**Recall@R** — какая доля из $R$ истинных ближайших соседей запроса возвращена алгоритмом.

Для запроса $q$ с множеством $R$-ближайших соседей $G_R(q)$ и множеством возвращённых кандидатов $C(q)$:

$$\operatorname{recall@R}(q) = \frac{|G_R(q) \cap C(q)|}{R}$$

Количество бит квантизации влияет на выбор $C(q)$ и, соответственно, на Recall.

# Алгоритмы

Для сравнения выбраны три алгоритма: perturbation, GMM (sklearn) и cuVS (базовый и с модификацией).

<div class="grid grid-cols-3 gap-6 mt-8 text-[15px] leading-snug">
<div>

**Perturbation**

Берём реальные точки выборки и добавляем к каждой гауссов шум. Идея: данные восстанавливаются как облако локальных вариаций вокруг настоящих точек, без явного моделирования кластеров

</div>
<div>

**GMM**

Распределение аппроксимируется смесью гауссовых компонент с диагональными ковариациями. Идея: кластер описывается центром и дисперсией по каждой координате, а сэмплирование из такой смеси дёшево и устойчиво

</div>
<div>

**cuVS**

Кластерно-геометрический генератор: явно задаёт центры кластеров, локальное подпространство внутри них и шум вне этого подпространства. Идея: воспроизвести геометрию эмбеддингов — кластеры, их локальную размерность и фоновый шум

</div>
</div>

# Гипотезы

**H1 (over-separation):**  
Perturbation-baseline завышает ρ(q) больше чем на 0.02: чистые гауссовы кластеры слишком хорошо отделимы друг от друга по сравнению с реальными эмбеддингами

**H2 (GMM captures variance):**  
Диагональная GMM точнее baseline воспроизводит recall@100 на каждом числе бит, потому что дисперсия по каждой координате -- предиктор первого порядка сложности квантизации

**H3 (all fail at low bits):**  
При 1–3 битах все методы недооценивают сложность LAION, так как ни один не воспроизводит его внутреннюю размерность (~24)

# Выводы

> **Какой метод использовать, чтобы генерировать синтетику для ANN-бенчмарков?**

<div class="mt-6">

- **Perturbation** — самый простой и единственный, который статистически неотличим от LAION по C2ST (0.52). Но он завышает ρ на оракуле на 0.115 и явно сложнее LAION при 1–3 битах
- **Диагональная GMM** ведёт себя почти как perturbation (C2ST 0.52, те же recall по битам), но портит распределение хабов ($N_{10}$ = 15.4)
- **cuVS** — единственный метод, у которого форма кривых ρ(q) и recall по битам ближе всего к LAION (C2ST 0.89, минимум бит 8 против 7), но он же сильнее всех ошибается по хабам и внутренней размерности (36.5 вместо 24.2)
- Ни один из трёх не воспроизводит LAION при 1–3 битах: по кодам все генераторы дают recall 0.38–0.67 против 0.739

</div>

# Ограничения и дальнейшая работа

**Ограничения**
- результаты специфичны для LAION/CLIP; на других моделях эмбеддингов картина может быть иной
- посчитан только пилот на 1M: проход на 10M остановлен из-за нехватки диска
- роутинг посчитан на одном seed разбиения (16 шардов, seed 81027), доверительных интервалов по seed'ам нет
- эталон LAION взят с другим seed разбиения (bkm16_s0), поэтому порог ±0.02 проверяется лишь грубо
- обучение GMM на выборке 100k с 1000 компонентами недоопределено

**Дальнейшие шаги**
- генераторы на основе нормализующих потоков (normalising flows) для большей точности распределения
- условная генерация, подстраивающаяся под распределение сложности запросов
- проверка на графовых индексах (HNSW, NSG), а не только на flat-протоколах
